# Negent

>  [نسخه فارسی](./README.fa.md)

A Telegram bot that aggregates tech news from RSS feeds, uses **Google Gemini** to pick the most important stories, summarizes and translates them into **Persian**, and delivers them — with an optional **Persian voice reading** — to subscribers on a schedule.

Built as a single **Cloudflare Worker** in TypeScript, backed by **D1** (SQLite). **Zero runtime dependencies.**

## How it works

```
RSS sources ──► fetch cron ──► raw articles (D1)
                                     │
                                     ▼
                          select cron (hourly)
                                     │
              ┌──────────────────────┼───────────────────────┐
              ▼                      ▼                        ▼
      Gemini selection      Gemini summarize/           Telegram delivery
      (top stories,          translate → Persian        (+ Persian voice
       cross-source dedup)                                reading, optional)
```

Two cron triggers drive everything:

- **`fetch`** (every 10 min) — pulls **one** RSS source per run (rotated), keyword-filters, dedups by URL hash, and stores new articles as `raw`.
- **`select`** (hourly, gated to Tehran daytime) — sends the newest raw titles to Gemini, which picks the top stories and dedups across sources. The picks are summarized/translated into informal Persian, delivered to active subscribers, and optionally read aloud as a Persian voice message.

### Voice readings

Voice is generated by the Gemini **Live API** audio model over a WebSocket, returning raw PCM that is wrapped in a WAV container (no dependencies) and sent via Telegram `sendAudio`. It is gated by `SEND_AUDIO` and is strictly best-effort — any failure is swallowed so text delivery is never blocked.

## Tech stack

- **Runtime:** Cloudflare Workers (TypeScript)
- **Storage:** Cloudflare D1 (SQLite) — the only store
- **AI:** Google Gemini (selection + summarization/translation + voice)
- **Delivery:** Telegram Bot API (webhook-based)
- **Dependencies:** none at runtime (RSS parsing is dependency-free regex; WAV encoding is hand-rolled)

## Getting started

### Prerequisites

- Node.js and npm
- A Cloudflare account with Wrangler configured
- A Telegram bot token (from [@BotFather](https://t.me/BotFather))
- A Google Gemini API key

### Setup

```bash
# Install dev dependencies
npm install

# Create a D1 database and update database_id in wrangler.toml
wrangler d1 create negent-db

# Apply the schema and seed the default RSS sources
npm run db:remote
npm run seed:remote

# Set secrets (not stored in the repo)
wrangler secret put BOT_TOKEN
wrangler secret put GEMINI_API_KEY

# Deploy
npm run deploy
```

For local development, create a `.dev.vars` file:

```
BOT_TOKEN=your-telegram-bot-token
GEMINI_API_KEY=your-gemini-api-key
```

Then register the Telegram webhook to point at `/webhook/<BOT_TOKEN>` on your deployed Worker.

## Commands

| Command | Description |
| --- | --- |
| `npm run dev` | Run the Worker locally at `http://localhost:8787` |
| `npm test` | Run the test suite once (Vitest) |
| `npm run test:watch` | Run tests in watch mode |
| `npm run deploy` | Deploy the Worker |
| `npm run tail` | Stream live logs from the deployed Worker |
| `npm run db:local` / `db:remote` | Apply `schema.sql` to D1 |
| `npm run seed:local` / `seed:remote` | Seed default RSS sources |
| `npx tsc --noEmit` | Typecheck (no lint script; TypeScript is `strict`) |

### Local cron testing

`wrangler dev` exposes the scheduled handler over HTTP (URL-encode spaces as `+`):

```bash
curl 'http://localhost:8787/__scheduled?cron=*/10+*+*+*+*'
```

## Bot commands

| Command | Who | Description |
| --- | --- | --- |
| `/start` | anyone | Subscribe (the first ever user becomes admin) |
| `/stop` | anyone | Unsubscribe |
| `/sources` | anyone | List the RSS feeds |
| `/status` | admin | Pipeline statistics |

Sources are managed via `seed.sql` — there are no add/remove bot commands.

## Project layout

```
src/
├── index.ts            # Worker entry: fetch (webhook/health) + scheduled (cron dispatch)
├── cron/
│   ├── fetch.ts        # Pull one RSS source, filter, dedup, store raw
│   ├── select.ts       # Select → summarize → produce `done` articles
│   └── deliver.ts      # Ship one `done` article (text + voice reply)
├── services/
│   ├── rss.ts          # Dependency-free RSS/Atom parser
│   ├── selector.ts     # Gemini story selection
│   ├── summarize.ts    # Gemini summarize/translate to Persian
│   ├── tts.ts          # Gemini Live API voice (WebSocket)
│   ├── telegram.ts     # Telegram Bot API client + message formatting
│   └── geminiClient.ts # Shared Gemini HTTP/retry/fallback/JSON utilities
├── bot/commands.ts     # Bot command handlers
├── utils/
│   ├── constants.ts    # All tuning knobs (batch sizes, hours, keywords, models)
│   ├── filter.ts       # Keyword filtering
│   ├── audio.ts        # PCM → WAV wrapping
│   ├── time.ts         # Tehran delivery-hours gate
│   └── cronRegistry.ts # Cron expression → handler registry
├── db.ts               # D1 queries
└── types.ts            # Env bindings + domain types
```

## Notes

- All user-facing text is **Persian, informal** ("تو" not "شما"), with tech terms kept in English.
- Delivery is timezone-aware: crons run in UTC but delivery is gated to Tehran daytime (UTC+3:30).
- Tuning knobs live in `src/utils/constants.ts`.
- See `AGENTS.md` for deeper architectural guidance and gotchas.
